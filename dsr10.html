Aula 10 — Pipelines de CI/CD, Automação e GitOps

Entrega contínua em ambientes distribuídos: automação de testes, build de imagens imutáveis, ambientes efêmeros e conciliação contínua com GitOps (ArgoCD).

CI/CD Distribuído

Linters, testes unitários, SAST, escaneamento de vulnerabilidades CVE e assunção de papéis temporários (OIDC).

Filosofia GitOps

O repositório Git como autoridade suprema (Single Source of Truth) para o estado da infraestrutura de produção.

Operadores & ArgoCD

Pull-based deployment: o cluster sincroniza a si próprio a partir do repositório, sem expor portas nem credenciais para fora.

1. Modelo Push (Tradicional) vs. Modelo Pull (GitOps)

Em soluções remotas, expor as chaves mestras de acesso do cluster Kubernetes para servidores de CI é um risco crítico.

Modelo Push (CI Tradicional)
  • A esteira de CI/CD (ex: GitHub Actions) precisa de um kubeconfig com privilégios de escrita.
  • Se a conta da plataforma de CI for comprometida, o invasor tem controle de todos os clusters.
  • O firewall do cluster precisa permitir conexões de entrada originadas de nós de CI externos.
Modelo Pull (GitOps)
  • Um agente interno (ArgoCD / Flux) roda dentro do próprio cluster.
  • O agente monitora o repositório Git e puxa as alterações (nenhuma porta externa aberta).
  • O cluster reconcilia desvios automaticamente; se alguém fizer um kubectl edit manual, o ArgoCD desfaz na hora.

2. Anatomia de uma Esteira de CI Moderna

Antes de gerar a imagem de produção, a esteira executa checagens obrigatórias em paralelo.

EtapaFerramentasObjetivo
1. Análise Estática & LintESLint, Ruff, SonarQubePadronizar estilo e prevenir bugs lógicos óbvios antes da compilação.
2. Prevenção a SegredosGitleaks, TruffleHogBloquear merge caso tokens de API ou certificados tenham sido incluídos por acidente.
3. SAST & SCASnyk, Trivy, DependabotValidar vulnerabilidades conhecidas (CVEs) em bibliotecas e dependências de terceiros.

3. Exemplo Prático: Pipeline GitHub Actions com OIDC

Construção de contêiner e push para o registry sem credenciais estáticas de longa duração.

name: Build & Release
on: { push: { branches: ["main"] } }
permissions:
  id-token: write # Obrigatório para autenticação via OIDC
  contents: read
jobs:
  build-and-push:
    runs-on: ubuntu-latest
    steps:
    - uses: actions/checkout@v4
    - name: Escanear Segredos
      uses: gitleaks/gitleaks-action@v2
    - name: Build da Imagem com Tag Semântica
      run: |
        docker build -t registry.empresa.com/dsr-api:${{ github.sha }} .
    - name: Escanear Vulnerabilidades na Imagem com Trivy
      uses: aquasecurity/trivy-action@master
      with:
        image-ref: 'registry.empresa.com/dsr-api:${{ github.sha }}'
        exit-code: '1'
        severity: 'CRITICAL'

4. ArgoCD: O Operador GitOps para Kubernetes

O ArgoCD implementa o loop de controle GitOps: compara a pasta do repositório Git com os manifestos vivos no cluster.

Estados Principais no ArgoCD
  • Synced: O estado no cluster reflete exatamente o commit atual do Git.
  • OutOfSync: Houve um novo commit no Git ou alguém alterou manualmente o cluster; o ArgoCD detecta a divergência.
  • Healthy: Todos os pods estão saudáveis e atendendo probes.
  • Degraded: Pods em CrashLoop ou Services sem endpoints disponíveis.
# ArgoCD Application Manifest
apiVersion: argoproj.io/v1alpha1
kind: Application
metadata:
  name: dsr-producao
spec:
  source:
    repoURL: https://github.com/org/k8s-manifests
    targetRevision: HEAD
    path: environments/prod
  destination:
    server: https://kubernetes.default.svc
  syncPolicy:
    automated:
      prune: true
      selfHeal: true

5. Estratégias de Deploy: Blue/Green e Canary

Em arquiteturas distribuídas, lançar atualizações sem interrupção de serviço requer divisão inteligente de tráfego.

Blue/Green Deployment
  • Mantém dois ambientes idênticos em paralelo: Blue (versão atual) e Green (nova versão).
  • O tráfego é direcionado 100% para o Green de uma só vez pelo roteador/ingress após validação completa.
  • Rollback instantâneo: Caso ocorra um erro, basta apontar o roteador de volta para o ambiente Blue.
Canary Deployment (com Argo Rollouts)
  • Encaminha uma pequena fração do tráfego real (ex: 5%) para a nova versão.
  • Métricas de erro (HTTP 5xx) e latência percentil são analisadas automaticamente via Prometheus.
  • Se as métricas permanecerem estáveis, o tráfego é incrementado gradativamente (10%, 25%, 50%, 100%). Se subirem os erros, o rollback é automático.

6. Preview Environments (Ambientes Efêmeros)

Equipes remotas não devem esperar que uma branch chegue a Staging para validar suas funcionalidades com clientes internos.

Fluxo de Trabalho: A cada novo Pull Request aberto no Git, a esteira cria um Namespace temporário exclusivo no Kubernetes (ex: `pr-142.empresa.dev`), faz o deploy dos microsserviços parametrizados e adiciona um comentário no PR com o link funcional para testes. Quando o PR é mergeado ou fechado, o ambiente efêmero é sumariamente destruído para economizar recursos de nuvem.

Exercício 3: Deploy Gradual e Análise Automática

Cenário: Uma equipe remota deseja lançar uma atualização de uma API crítica sem arriscar que uma exceção não mapeada afete a base inteira de usuários. Eles querem que a nova versão receba apenas 10% do tráfego e que seja revertida automaticamente caso a taxa de erros HTTP 500 suba.

Exercício 4: O Risco da Tag `:latest`

Cenário: Em um ambiente Kubernetes gerenciado via GitOps, os manifestos utilizam a tag `image: minha-api:latest`. Durante a noite, novos Pods escalados entram em conflito com Pods antigos porque o container runtime não baixou o binário novo.

Módulo Concluído

Entrega Contínua em Ambientes Remotos

A automação com GitOps desacopla quem escreve código de quem administra a infraestrutura física de execução.

Segurança Máxima

Elimine chaves de cluster de terceiros. Use OIDC na esteira de integração e deixe agentes GitOps internos realizarem o sync de forma declarativa.

Previsibilidade Operacional

Adote tags imutáveis, canary releases com validação por métricas e ambientes efêmeros por PR para validar entregas com agilidade.
